# 보안 설계 — 주문조회 · 관리자 시스템

> 2026-10-20 작성. 요구사항: ① 다른 회사가 우리 거래처를 알 수 없어야 한다 ② 주문한 거래처만 자기 주문을 본다 ③ 관리자(DB) 시스템에는 외부인이 절대 들어올 수 없다.

## 1. 지금(중간 MVP, GitHub Pages 정적 사이트)에서 한 것

| 항목 | 구현 | 한계 |
|---|---|---|
| 주문조회 | 주문번호 **+ 6자리 조회 코드**가 모두 맞아야 표시 | 정적 사이트라 데모 데이터가 브라우저에 내려감 → **실제 주문은 절대 넣지 않음** (가상 데모 3건만) |
| 조회 코드 보관 | 원문 대신 `SHA-256(주문번호:코드)` 해시만 저장 | 6자리 숫자는 해시만으로는 대입 공격에 약함 → 정식 서비스는 서버 확인 필수 |
| 거래 여부 노출 방지 | 실패 시 "주문번호 또는 조회 코드가 맞지 않습니다" 한 가지 문구만 표시 | — |
| 무작위 대입 방지 | 5회 연속 실패 시 30초 잠금 | 브라우저 새로고침으로 초기화됨 → 정식 서비스는 서버에서 제한 |
| 검색 노출 | 주문조회 페이지 `noindex` | — |
| 관리자 기능 | 공개 사이트에 **넣지 않음** | — |

## 2. 정식 서비스(11월~) 구조

```
[공개 사이트]  Next.js on Vercel
   주문조회 화면 ── POST /api/orders/lookup ──┐
                                             ▼
                              [서버 API] 조회 코드 검증·속도 제한·로그
                                             ▼
                              [DB] Supabase Postgres + RLS
                                             ▲
[관리자 앱]  admin.도메인 (별도 배포) ─────────┘
   직원 로그인 + 2단계 인증 → 문의·견적·주문·납기·콘텐츠 관리
```

### 주문조회 (거래처)
- **방식 A — 조회 코드(기본):** 주문 확정 시 거래처 담당자에게만 문자·메일로 조회 링크(긴 무작위 토큰) 또는 6자리 코드를 보냄. 서버가 해시(bcrypt/argon2)로 비교, 주문번호·IP 기준 시도 횟수 제한, 실패 응답은 항상 동일.
- **방식 B — 거래처 로그인(선택):** 재주문이 많은 거래처에 계정 발급. Supabase Auth, 거래처 계정은 `customer_id`에 묶이고 DB 정책(RLS)으로 **자기 거래처 주문만** 조회.
- 주문 데이터는 **서버에만** 존재. 브라우저 코드·저장소에 넣지 않음.
- 응답에는 필요한 최소 정보만: 주문번호, 품목 요약, 진행 단계, 예상 완료일. 단가·담당자 연락처·다른 주문 정보는 제외.

### 관리자 시스템 (직원)
- **별도 앱·별도 주소** — 공개 사이트 코드에 관리자 화면·키가 섞이지 않음.
- 로그인 필수 + **2단계 인증(OTP)**, 직원 계정은 대표가 직접 발급(회원가입 화면 없음).
- 권한 구분: 대표(전체) / 직원(문의·주문 상태 수정) — DB 정책(RLS)으로 강제.
- 선택: 회사 IP 대역에서만 접속 허용, Vercel/Cloudflare 접근 제어.
- 모든 변경에 기록(누가·언제·무엇을) 남김.
- 비밀값(DB 서비스 키, 알림톡 키, 세금계산서 API 키)은 **서버 환경변수에만**. GitHub에는 이름만, 값은 GitHub Secrets / Vercel 환경변수.

### 개인정보
- 거래처·고객 정보를 저장하는 시점부터: 개인정보처리방침 게시, 수집 동의, 보관 기간, 접근 기록, 파기 절차.

## 3. 비밀값 이중 관리 (교수님 안내 사항)

| 위치 | 용도 | 방법 |
|---|---|---|
| 내 컴퓨터 | 개발 | `.env.local` — `.gitignore`로 커밋 차단 |
| GitHub Secrets / Vercel 환경변수 | 배포 | 저장소 설정에만 저장, 화면에 다시 표시되지 않음 |

코드에는 `process.env.이름`만 적는다. 브라우저로 내려가는 코드(`NEXT_PUBLIC_*`)에는 비밀값을 절대 쓰지 않는다.
