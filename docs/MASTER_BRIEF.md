## 0. 기획 변경 (2026-10-20 대표 인터뷰)

- 회사는 기성품이 아니라 **개발**을 한다. 소재는 **대표가 직접 추천**한다.
- 세척만 해도 기차·버스·신발·가리비·무 등 대상이 방대하고, 연마용은 용도마다 모양·크기가 다르며, 철강도 표면 세척인지 물기 제거인지에 따라 전혀 다르다.
- 충분한 기술과 경험이 있어야 만들 수 있고, 시중 브러쉬와 차원이 다르다.

**결정:** ① 포지셔닝을 "시중 브러쉬로 해결되지 않는 공정을 위해 브러쉬를 개발하는 회사"로 변경 ② AI 기능을 형태·소재 **추천**에서 **개발 의뢰서(문제 구조화)** 로 변경 — 소재·구조는 대표가 제안 ③ 메뉴를 제품 분류 대신 적용 분야·개발 프로세스·개발 사례 중심으로 변경 ④ 적용 분야 8개(대표 확인) 공개

## 2. 현재 홈페이지의 문제 → 해결 방향

| # | 현재 문제 | 원인 (추정) | 해결 방향 | 단계 |
|---|---|---|---|---|
| 1 | 기존 사이트(jeilbrush.com/shop) 접속 시 브라우저가 "위험" 경고 | HTTPS 미적용 또는 Google 세이프 브라우징 차단(해킹·악성코드 의심) | 새 사이트는 HTTPS 기본 제공 호스팅 사용. 기존 사이트는 관리업체(부산인터넷방송국)에 점검 요청 | 1단계(새 사이트) / 즉시(점검 요청) |
| 2 | 견적문의가 와도 알림이 없어 놓침 | 게시판형 문의, 알림 기능 없음 | 문의 → DB 저장 → **담당자 휴대폰(카카오 알림톡/문자) + 메일 즉시 알림** | 2단계 |
| 3 | 문의 창구가 분산, 카톡 채널 활용 저조 | 채널마다 입력 방식이 다르고 유도 동선이 없음 | **사람과의 대화는 카카오 채널로 일원화.** 홈페이지는 상담 전 정보를 정리해 카카오로 넘겨주는 역할 | 1단계(복사→카카오) / 2단계(자동 전달) |
| 4 | 카탈로그·영상 부재 | 자료 미제작 | 자료실(카탈로그 PDF), 영상 섹션(YouTube + AI 제작 영상) | 1단계(틀) / 11월(콘텐츠) |
| 5 | 검색·AI 검색에 회사가 잘 안 나옴 | 콘텐츠 부족, 기술 SEO 부재 | 기술 SEO + 회사 정보 일관성 + 전문 콘텐츠 축적 (아래 7절) | 11월~ |
| 6 | 네이버·구글 동시 노출, 다국어 필요 | 등록 안 됨, 단일 언어 | 네이버 서치어드바이저 + 구글 서치콘솔 등록, 한/영/일/중 4개 언어 | 11월 |
| 7 | 브러쉬 지식 없는 구매담당자의 불완전한 문의 → 시간 낭비 | 무엇을 적어야 하는지 모름 | **AI 제작상담**: 질문에 답하면 후보·확인 필요 규격·문의 요약을 자동 정리 | **1단계 핵심(중간고사)** |
| 8 | 견적서·세금계산서 발급 방식이 구식 | 한글 문서 + 수기 | 견적서 관리 → 전자세금계산서 발행 대행 API 연동 검토 (아래 9절) | 3단계 |

| 구조화 데이터 (Organization, LocalBusiness, Product, FAQ) | AI·검색엔진의 회사 정보 이해 | 11월 |
| 상호·주소·전화 표기를 모든 곳에서 동일하게 | AI가 같은 회사로 인식 | 즉시 |

| `llms.txt` (AI용 회사 요약 파일) | 비용이 거의 들지 않는 보조 수단 | 11월 |

하지 않을 것: 키워드 반복 삽입, 지역명만 바꾼 가짜 페이지, "국내 1위" 같은 근거 없는 표현

## 9. 견적서·전자세금계산서 검토

**결론: 견적·세금계산서 "사이트"는 직접 만든다. 국세청 "전송"만 인증된 발행 대행 API에 맡긴다.**

```
[직접 개발 — 관리자 페이지]                       [외부 API]
견적 작성 → PDF → 고객 승인 → 수주 → 세금계산서 작성 → 발행 버튼 ──→ 발행 대행사(팝빌·바로빌 등) ──→ 국세청
       ↑ 화면·데이터·흐름은 전부 우리 것                        ↑ 인증서·전송 규격·보관은 대행사 책임
```

| 항목 | 내용 |
|---|---|
| 직접 만드는 부분 | 견적서 양식·번호 체계, 품목·단가, 공급가액·부가세 계산, PDF, 고객 승인 링크, 수주 전환, 세금계산서 작성 화면, 발행 이력·상태 조회 |
| API에 맡기는 부분 | 국세청 전송, 공동인증서 서명, 발행 결과 수신, 법정 보관 |
| 국세청 전송까지 직접 구현 | ❌ 국세청 표준 인증을 받은 시스템 사업자 수준의 요건이 필요해 1개 회사가 하기엔 비현실적 |
| 현행 의무 (확인 필요) | 법인은 전자세금계산서 의무 발행, 개인사업자는 공급가액 기준으로 의무 대상 여부가 정해짐 |

⚠️ **2026년 세법 기준, 회사 사업자 유형(법인/개인), 발행 기한·수정발행 규정은 담당 세무사 확인 후 개발한다.**

## 10. 전체 시스템 구조

```
┌──────────────── 공개 홈페이지 (누구나) ────────────────┐
│ 회사소개 · 제품·소재 · 솔루션(산업별) · 기술·설비        │
│ 자료실(카탈로그·영상) · AI Brush Finder · 문의/카카오    │
└──────────────┬─────────────────────────────────────────┘
               │ 문의·상담 요약 저장 (서버 API)
               ▼
        ┌────────────── 백엔드 ──────────────┐
        │ DB · 인증 · 파일 저장 (Supabase 등) │──→ 알림: 카카오 알림톡/문자/메일
        │ 서버 API (Vercel)                  │──→ 전자세금계산서 대행 API
        └──────────────┬─────────────────────┘──→ Notion API · LLM API
                       ▲
┌──────────────── 관리자 페이지 (직원만, 완전 분리) ────────┐
│ 로그인(2단계 인증) · 문의 CRM · 고객정보 · 견적관리        │
│ 세금계산서 · 주문 제작 현황 · 제품/콘텐츠 관리              │
│ Notion 콘텐츠 캘린더 · 블로그 일정 · SEO 키워드 · AI 초안   │
└──────────────────────────────────────────────────────────┘
```

- **완전 분리:** 관리자 페이지는 별도 앱·별도 주소(예: admin.도메인). 공개 사이트 코드에 관리자 기능이나 키가 섞이지 않음
- **기술:** Next.js + TypeScript (공개 사이트·관리자 동일 스택), Vercel, Supabase(DB·인증·저장소)
- **보안:** 직원 계정만, 2단계 인증, 권한 구분(대표/직원), DB 행 단위 보안(RLS), 모든 키는 서버 환경변수
- **개인정보:** 고객정보를 저장하는 순간부터 개인정보처리방침, 수집 동의, 보관 기간, 접근 기록 필요
