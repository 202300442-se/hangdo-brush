# 항도제일특수브러쉬 — AI 개발 의뢰서 MVP

> 2026학년도 2학기 기술개발연구프로젝트 · 중간 MVP (개인 과제)
> 실제 회사(항도제일특수브러쉬) 홈페이지 리뉴얼의 1단계 결과물입니다.

> ✍️ 표시가 있는 문단은 **본인(김시은)이 직접 다시 써야 하는 부분**입니다. 제출 전 지우고 본인의 말로 채웁니다.

---

## 1. 목적

항도제일특수브러쉬는 기성품을 파는 회사가 아니라, 고객 공정에 맞춰 브러쉬를 **개발**하는 회사입니다. 소재와 구조는 대표가 공정을 보고 직접 제안합니다. 그런데 문의하는 고객은 브러쉬 지식이 없어 "무엇을, 어떤 상태로 만들고 싶은지"를 충분히 전하지 못합니다.

이 서비스는 고객이 질문에 답하기만 하면 **대표가 바로 판단할 수 있는 개발 의뢰서**가 만들어지도록 돕습니다. 의뢰서는 카카오톡 채널이나 메일로 보내며, 회사는 기본 정보를 다시 묻지 않고 바로 검토를 시작할 수 있습니다.

✍️ (이 프로젝트를 왜 시작했는지 — 회사 현장에서 직접 본 문제를 1~2문장으로)

**기획 변경 기록 (2026-10-20)** — 처음에는 "브러쉬 형태·소재 추천" 기능으로 설계했습니다. 대표 인터뷰에서 ① 회사는 기성품이 아니라 개발을 하고 ② 소재는 대표가 직접 추천하며 ③ 세척 하나만 해도 기차·버스·신발·가리비·무 등 대상이 매우 넓어 분류로 추천할 수 없다는 답을 들었습니다. 그래서 추천을 빼고 **고객의 문제를 구조화하는 의뢰서**로 바꿨습니다.

## 2. 사용자와 줄이려는 불편

| 구분 | 내용 |
|---|---|
| **사용자 (한 유형)** | 산업용 브러쉬 전문지식이 부족한 **기업 구매담당자** |
| **줄이려는 불편** | 무엇을 적어야 할지 몰라 불완전한 개발 문의를 남기고, 담당자와 여러 번 연락을 주고받으며 기본 조건을 다시 확인해야 하는 불편 |
| **핵심 흐름** | 홈 → **AI 개발 의뢰서** → 4단계 질문 (모르면 "잘 모르겠습니다") → 의뢰 요약·확인된 조건·**아직 필요한 정보(이유 포함)**·검토 포인트·유사 적용 분야 → **의뢰서 복사** → 카카오톡/메일로 전달 |

## 4. 사용법

1. 공개 주소에서 **[AI 개발 의뢰서 작성]** 을 누릅니다.
2. **1단계 해결할 문제** — 하려는 작업(세척, 물기 제거 등)을 고르고, 브러쉬가 닿는 대상을 적습니다 (이 두 항목만 필수). 예: `가리비`, `버스 차체`, `냉연 강판 표면`
3. **2~3단계** — 작업 방식, 움직임, 환경, 표면 민감도, 치수를 아는 만큼만 답합니다. 모르면 "잘 모르겠습니다" / "치수를 모릅니다"를 고르고 넘어갑니다.
4. **4단계** — 수량·납기·보낼 수 있는 자료를 고르고 **[의뢰서 만들기]** 를 누릅니다.
5. 결과에서 의뢰 요약, 확인된 조건, **아직 필요한 정보와 그 이유**, 기술 검토 포인트, 함께 보낼 자료, 유사 적용 분야를 확인합니다.
6. **[의뢰서 복사]** → **[카카오톡으로 보내기]** 로 채팅창에 붙여 넣거나 **[메일로 보내기]** 를 누릅니다.

부가 기능: 적용 분야 검색(`/applications/`), 개발 사례 사진, 회사소개, 주문조회 데모(`/order/`, `HJ-DEMO-001`~`003`)

**상태 확인 방법 (검증용)**

| 상태 | 확인 방법 |
|---|---|
| 로딩 | 마지막 단계에서 [의뢰서 만들기] → 약 0.6초간 표시 |
| 정상 | 작업 "세척" + 대상 `가리비` → 유사 적용 분야 "수산물 세척" |
| 빈 결과 | 작업 "이송·가이드·차단" + 대상 `반도체 웨이퍼 캐리어` → "등록된 유사 적용 분야가 없습니다" 안내 / 적용 분야 검색에 `우주선` |
| 오류 | 주소 끝에 `?simulate=error` 를 붙여 진행 (예: `/finder/?simulate=error`) |
| 잘못된 입력 | 필수 항목 비우기, 외경에 `abc`, 회전 속도에 `12.5`, 수량에 `2.5`, 지난 날짜 납기, 검색어 `!!!`, 주문번호 `INVALID` |

**개인정보·보안**
- 이름·연락처 등 **개인정보를 수집·저장하지 않습니다.** 입력 내용은 브라우저 안에서만 처리되고, 사용자가 직접 복사해 보낼 때만 회사로 전달됩니다. 메모 칸에 개인정보를 적지 말라고 안내합니다.
- 서버·DB·외부 API를 쓰지 않으므로 **인증키가 없습니다.** 저장소에 비밀값이 없고 `.gitignore` 로 `.env*` 파일 커밋을 막아 두었습니다. 이후 키가 필요해지면 GitHub Secrets / Vercel 환경변수에만 저장하고, 브라우저 코드에서는 쓰지 않습니다.
- 방문 분석 도구, 쿠키, 로그인이 없습니다.

## 7. 알려진 한계

- **AI 모델을 쓰지 않는 규칙 기반 정리 도우미**입니다. 이름은 "AI 개발 의뢰서"지만 현재는 정해진 규칙으로 필요한 정보와 검토 포인트를 정리합니다. (11월 이후 LLM + 회사 지식으로 전환 예정)
- 브러쉬 형태·소재는 **추천하지 않습니다.** 대표가 공정을 확인한 뒤 직접 제안하는 회사 방식에 맞춘 의도된 제한입니다.
- 유사 적용 분야는 **검색어 일치** 방식이라, 등록된 표현과 다르게 쓰면 찾지 못할 수 있습니다.
- 의뢰서는 **자동 전송되지 않습니다.** 사용자가 복사해 보내야 하며, 카카오톡 채널은 채팅창에 내용을 미리 채울 수 없습니다.
- 사진·영상 **업로드 기능이 없습니다.** 카카오톡·메일에 직접 첨부하도록 안내합니다.
- 주문조회는 **가상 데이터**입니다. 회사 생산 일정은 아직 종이로 관리됩니다.
- 사진 설명은 외형을 보고 작성했으며 회사 확인 전입니다. 공식 로고 파일은 아직 받지 못해 임시 "HJ" 표시를 씁니다.
- 한국어만 지원합니다.

## 개발

```bash
npm install
npm run dev            # 개발 서버 http://localhost:3000
npm test               # 단위 테스트
npm run lint           # 타입 검사
npm run build:pages    # GitHub Pages용 빌드 (out/)
npm run preview        # http://localhost:4173/hangdo-brush/
```

구조: `UI(features/*) → services/* → engine(features/finder/engine.ts) + data/*`
적용 분야는 `src/data/applications.ts`, 개발 프로세스는 `src/data/process.ts` 만 고치면 화면 코드 수정 없이 바뀝니다. 전체 기획은 [docs/MASTER_BRIEF.md](docs/MASTER_BRIEF.md) 참고.
